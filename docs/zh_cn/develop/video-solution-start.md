# 新聊天制作一关解谜：最小入口

目标：一关一个工作目录，优先用新建聊天处理下一关，通过文件交接。
首轮只读取本文件、目标关材料、相关 Schema/动作规范及一份相近的正式解法。
AGENTS.md 和适用技能的必读要求仍然遵守。

## 可复制的启动提示词

发送以下内容并替换占位项：

```text
按 docs/zh_cn/develop/video-solution-start.md 完成一关解谜。
关卡：<完整题名，注明学习/熟练运用和分组>
视频：<B站完整链接>，仅处理 P<编号>。
目标目录 ID：<已知则填写；未知时从当前目录匹配>。

优先复用已有工具和该关本地素材。先读最小入口、目标关证据/草稿、
相关格式规范及一份相近解法；按需补读，不加载其他关的研究历史或整份卡库。
先看1–2张概览定位动作，再补读必要局部帧；不要发送全部采样帧。
核对当前游戏版本、手动/自动进化、抽牌及离场后的序号，形成固定语义解法。

可以操作 MuMu 中的《影之诗》完成从列表开始、通关并返回列表的实机验收。
接入正式解法、生成接口，并运行项目要求的检查；不提交或推送。
只保留简短进度、失败摘要和结果路径。结束时更新 evidence.md 的交接摘要，
记录可取得的实际用量；没有实际模型或 token 数据时明确标为未知。
```

若只制作候选稿、不操作模拟器，把实机授权两句替换为“本次只生成并静态校验候选稿”。
提示词中的“模型”是记录要求；发送前在聊天界面选择模型。

恢复已有工作时，把关卡/视频几行替换为：

```text
继续 artifacts/puzzle-video/<BV>_p<P>/evidence.md 中未完成的工作。
先读取交接摘要和当前解法，不重新分析已确认步骤；仅补读列出的缺失证据。
```

## 工具和材料

- 已有环境：`.ai-tools/video/Scripts/python.exe`；异常或首次使用才运行 `tools/setup_video_tools.ps1`。
- 工具：`tools/puzzle_video.py` 的 `download`、`prepare`、`validate`；参数不清楚时先读对应 `--help`。
- 本地关卡：`artifacts/puzzle-video/<BV>_p<P>/`；已有视频不重复下载。
- 正式解法：`assets/resource/solutions/<id>.json`；目录已有 ID 时不重复新增。
- 格式：`assets/schemas/solution.schema.json`、`docs/zh_cn/solution-format.md` 中相关动作。
- 完整操作说明：[视频转解法流程](./video-to-solution.md)，需要细节时再读相关小节。

文件路径由脚本结果确认，不能假定 run 子目录或视频扩展名。
概览缩略图只用于定位，卡名、目标线、数值及按钮需用原尺寸局部证据确认。
脚本准备素材及做机械校验；模型只处理动作含义、状态变化和固定解法成立依据。

## 每关结束的交接摘要

把下面内容置于 `evidence.md` 顶部，详细失败记录放在后面，下一聊天先读顶部即可：

```text
关卡 / 目录ID / 游戏版本：
来源链接 / 分P / 本地视频：
当前状态：素材已准备 / 证据已核对 / 静态校验通过 / 实机通过
当前解法路径及步骤数：
确认的初始状态、关键效果和随机成立依据：
关键帧清单：源时间 + 路径（只列必要帧）
待解决问题及下一步：没有则写无
验证结果：命令、退出码、实际完成/返回列表证据
实际用量：输入 / 缓存输入 / 输出含推理；未知则保持未知
```

减少旧聊天和大段工具输出；保留必要验证。新聊天仍会读取项目说明，
无法承诺固定 token 数量或节省百分比，需用后续实测校准。
